# Резервна копія розкладу ФМІ

Статична сторінка, яка показує розклад занять, коли основний сайт
[fmi-schedule.chnu.edu.ua](https://fmi-schedule.chnu.edu.ua) недоступний.
Бекенд, база даних і збірка не потрібні: є одна HTML-сторінка і JSON-файли
з розкладом, які раз на пів години вивантажуються з основного застосунку.

## Що вміє сторінка

- **Список семестрів.** Стартова сторінка показує семестри, які ще не закінчились
  (`disable: false`, `endDay` не раніше сьогодні).
- **Три подання**, як в основному застосунку: «Загальний» (усі групи, з фільтром
  за курсом), «Група», «Викладач». Є пошук за предметом і викладачем.
- **Звичайний семестр** показується з непарним і парним тижнем. Поточний тиждень
  рахується так само, як в основному застосунку: перший тиждень семестру непарний,
  відлік від понеділка `startDay`. Наступний тиждень приглушений.
- **Короткий семестр** (не довший за 14 днів, наприклад сесія) і семестр
  із `scheduledByDate: true` показуються за конкретними датами. Минулі дні приглушені,
  сьогоднішній виділений.
- **Порядок груп** береться з `semester_groups` (для семестру за датами — з `groups`),
  тобто він такий самий, як в основному застосунку.
- **Сьогоднішній день** виділений, і таблиця одразу прокручується до нього.
- **Пошук** показує кількість знахідок («3 з 12»), між ними можна переходити кнопками ▲▼
  або Enter / Shift+Enter. Якщо в поточному поданні нічого немає, а в семестрі є,
  сторінка підкаже, де шукати.
- **На телефоні** замість широкої таблиці сторінка пропонує обрати групу і запам'ятовує вибір
  на цьому пристрої (`localStorage`, окремо для кожного семестру). У приватному режимі
  браузера вибір не зберігається.
- **Посилання** мають той самий вигляд, що й в основному застосунку:
  `?semester=61&group=51`, `?semester=61&teacher=70`. Пряме посилання завжди має пріоритет
  над запам'ятованим вибором.

## Файли

| Файл | Що це | Звідки береться |
|---|---|---|
| `index.html` | сама сторінка | змінюється вручну |
| `semesters.json` | список семестрів | `GET /public/semesters` |
| `full-<id>.json` | повний розклад семестру | `GET /schedules/full/semester?semesterId=<id>` |
| `export-schedule.sh` | скрипт вивантаження для крона | — |

`/schedules/full/semester` повертає один із двох форматів, і сторінка розуміє обидва:

- тижневий: `{semester, schedule[]}`;
- за датами (`scheduledByDate`): `{semester, teacher, dates[], periods[], groups[], items[]}`.

Якщо `semesters.json` немає, сторінка показує один `full.json` (режим одного семестру).

## Оновлення даних

`export-schedule.sh` запускається кроном на mathserver і звертається до застосунку
напряму через `http://localhost:8080`:

1. Зберігає список семестрів у `semesters.json`.
2. Для кожного семестру з `disable: false`, який ще не закінчився, зберігає `full-<id>.json`.
3. Якщо щось змінилось, робить коміт і пуш.

Файл замінюється тільки валідною відповіддю. Якщо застосунок не працює або розклад
не опублікований, попередня копія лишається, а в лог пишеться рядок
`semester <id>: export failed, keeping the previous file`.
Файли семестрів, що закінчились, не видаляються, їх просто не видно у списку.

Потрібні `curl`, `jq`, `git`.

### Налаштування на сервері

```bash
# deploy key just for this repo (GitHub → Settings → Deploy keys, "Allow write access")
ssh-keygen -t ed25519 -N "" -C "mathserver schedule-fallback" -f ~/.ssh/schedule_fallback

cat >> ~/.ssh/config <<'EOF'
Host github-fallback
  HostName github.com
  User git
  IdentityFile ~/.ssh/schedule_fallback
  IdentitiesOnly yes
EOF

git clone git@github-fallback:<owner>/<repo>.git ~/schedule-fallback
cp ~/schedule-fallback/export-schedule.sh ~/bin/ && chmod +x ~/bin/export-schedule.sh
~/bin/export-schedule.sh          # first run by hand
```

Якщо порт 22 закритий, використовуйте `HostName ssh.github.com` і `Port 443`.

crontab (`crontab -e`):

```
*/30 * * * * $HOME/bin/export-schedule.sh >> $HOME/export-schedule.log 2>&1
```

Шляхи можна змінити змінними оточення: `API` (за замовчуванням `http://localhost:8080`)
і `REPO` (за замовчуванням `~/schedule-fallback`).

## Як переглянути локально

Сторінку треба відкривати через вебсервер, бо з `file://` браузер не дає читати
сусідні JSON-файли:

```bash
cd ~/schedule-fallback
python3 -m http.server 8000      # then open http://localhost:8000
```

Якщо все ж відкрити `index.html` з диска, сторінка попросить обрати JSON-файли вручну.

## Якщо щось не так

- **«Для семестру … немає резервної копії».** Немає файлу `full-<id>.json`: семестр
  не вивантажився (див. лог крона), або сторінка відкрита з диска. Файл можна обрати вручну
  прямо на цьому екрані.
- **У списку немає потрібного семестру.** Він закінчився або має `disable: true`.
  За прямим посиланням `?semester=<id>` він відкриється, якщо файл є.
- **Дані застарілі.** Дату знімка видно в жовтому банері вгорі. Перевірте
  `~/export-schedule.log` і чи пройшов `git push`.
